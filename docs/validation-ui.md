# 고운마음 콘솔 · 검증(Validation) · 피드백 UI 규칙

> 지금까지 콘솔(v3)에 실제로 쓴 패턴을 정리한 문서. 컴포넌트는 IRIS 기준.
> 원칙: **입력 중에는 자리에서 알려주고, 행동 결과는 무게에 맞는 방식으로 알려준다.**

## 1. 무엇을 쓸지 고르는 기준

```
입력하는 중인가?
 ├─ 예 → 필드 아래 안내(2-1) · 실시간 체크(2-3) · CTA 비활성(2-4)
 │        제출했는데 서버/규칙에서 막힘 → 인라인 오류 박스(2-2)
 └─ 아니오(행동을 했다)
     ├─ 되돌릴 수 없거나 돈·발송이 나가는 행동 "전" → Alert 확인(3-2)
     ├─ 결과를 확인하고 다음 행동을 골라야 함 "후" → 완료 모달(3-3)
     ├─ 가벼운 저장·처리 "후" → Toast(3-1)
     └─ 화면에 계속 떠 있어야 하는 주의·안내 → SectionMessage(2-5)
```

금지: 입력 오류를 팝업으로 알리기 · 가벼운 저장에 완료 모달 띄우기 · 토스트 안에 버튼 넣기.

## 2. 입력 중 (인라인)

| # | 패턴 | 컴포넌트 · 모양 | 언제 | 문구 예 | 쓰인 곳 |
|---|---|---|---|---|---|
| 2-1 | 필드 하단 안내 | 필드 아래 13px `label-alternative` | 입력 전 도움말 · 입력값에 따른 결과 예고 | "3분 안에 입력하세요" / "정책 금액 · 결재 없이 이체됩니다" | 로그인 인증번호, 경조금 금액, 예금주 조회 |
| 2-1b | 하단 안내 · 주의 | 같은 자리, 주황 `#8A4B00` | 막지는 않지만 알아야 할 것 | "정책 금액 ₩500,000과 다릅니다 · 승인 후 이체됩니다" | 경조금 금액 변경 |
| 2-2 | 인라인 오류 박스 | `red-95` 배경 + `triangle-exclamation-fill` + 본문 + (선택) 해결 `TextButton` | 제출 후 규칙·서버에서 막힘 | "등록되지 않은 번호예요. 회사 경조사 담당자에게 등록을 요청하세요." + [비밀번호 재설정] | 로그인 · 처음 로그인 · 재설정 |
| 2-3 | 실시간 규칙 체크 | 규칙마다 `check` 아이콘 (충족: 초록 / 미충족: 회색) | 조건이 여러 개인 입력 | "8자 이상" "영문 · 숫자 포함" "두 번 입력한 비밀번호가 같음" | 비밀번호 만들기 |
| 2-4 | CTA 비활성 | `Button disabled` | 필수 입력이 안 됐을 때 | — | 로그인, 인증번호 받기, 다음, 동의하고 다음, 추가(수신인) |
| 2-4b | 남은 할 일 목록 | 요약 패널 CTA 아래 주황 박스 · 항목 나열 | 비활성 CTA의 이유가 화면 밖에 있을 때 | "· 받는 사람을 선택하세요" "· 입금 계좌의 예금주를 조회하세요" | 경조금 · 화환 보내기 |
| 2-4c | 단계 버튼 상태 | 채움(할 차례) → 테두리 회색 + `check` "조회 완료"(끝남) | 순서가 있는 확인 절차 | "예금주 조회" → "조회 완료" | 경조사 상세 이체 실패 재입력, 보내기 계좌 |
| 2-5 | SectionMessage | `info`(파랑) / `cautionary`(주황) / `negative`(빨강) · 선택 액션 | 화면 · 모달 상단에 계속 보여야 하는 안내 | "서울추모공원은 3단 화환 반입이 제한됩니다" [대체 상품 보기] | 화환 상품, 규정 적용, 법인카드 한도, 모든 폼 모달 상단 |
| 2-6 | 카운트 · 제한 표시 | 필드 오른쪽 빨간 타이머 · 오류 문구 끝 "(n/5)" | 시간 · 횟수 제한 | "2:59" / "(1/5)" | 인증번호, 비밀번호 실패 |

**필드 오류 표시 규칙:** 형식 오류(번호 자릿수 등)는 IRIS TextField `invalid`(빨간 링) + 필드 바로 아래 빨간 13px 한 줄로 표시한다. 입력 중에는 띄우지 않고, 틀린 것이 확실해진 시점(예: 앞 3자리가 010이 아님, 10자리 이상인데 형식 불일치)에 띄운다. **적용:** 로그인 · 본인 확인의 휴대폰 번호 ("010으로 시작하는 휴대폰 번호 10~11자리를 입력하세요"), 비밀번호 확인 ("비밀번호가 서로 다릅니다").

## 3. 행동 후 (피드백)

| # | 패턴 | 컴포넌트 | 언제 | 문구 예 | 쓰인 곳 |
|---|---|---|---|---|---|
| 3-1 | Toast | `Toast` · 화면 하단 · 2.4초 후 자동 사라짐 · 버튼 없음 | 가벼운 저장 · 처리 완료, 화면에 결과가 바로 반영될 때 | "저장했습니다" "정재훈 사원 결혼 축하금을 승인했습니다" "증빙 제출을 요청했습니다" | 설정 저장, 홈 빠른 승인, 증빙 요청, 폼 모달 대부분 |
| 3-2 | Alert (확인) | `Alert` · 가운데 · 딤 · [취소] + [실행] (위험하면 `negative`) | 되돌릴 수 없음 · 돈이 나감 · 외부로 발송됨 "전" | "이 경조사를 취소할까요?" "이 카드를 삭제할까요?" | 로그아웃, 경조사 취소, 삭제류, 결제 반려, 빠른 승인 |
| 3-3 | 완료 모달 | `Modal` + 성공 아이콘 + 결과 요약 + 다음 행동 2개 | 이체 · 발송 · 접수처럼 결과를 확인해야 하고 다음 할 일이 이어질 때 | "화환을 주문했습니다" [경조사 보기] [하나 더 보내기] | 화환 · 경조금 · 부고장 보내기, 경조사 접수 |
| 3-4 | 상태 배지 + 자리 수정 | 표 · 목록의 `ContentBadge` (실패 = 빨강) + 그 행에서 바로 재입력 | 처리 결과가 나중에 실패로 돌아왔을 때 | "이체 실패" → 계좌 다시 입력 → [다시 보내기] | 경조사 상세 · 보낼 것 |
| 3-5 | 빈 상태 | `FallbackView` · 제목 + 설명 + (선택) CTA 1개 | 목록 · 검색 결과가 비었을 때 | "보낸 화환이 없습니다" / "검색 결과가 없습니다" | 모든 목록, 검색, 빈 상태 전환 |

## 4. 문구 규칙

| 구분 | 규칙 | 예 |
|---|---|---|
| 오류 | 무엇이 문제인지 + 어떻게 푸는지. 사용자 탓 표현 금지 | "비밀번호가 맞지 않습니다. 5회 틀리면 10분간 로그인이 제한됩니다." |
| 안내 | 결과를 먼저 | "규정 금액과 같으면 결재 없이 바로 이체됩니다" |
| 완료 | 한 일을 과거형으로, 대상 포함 | "정재훈 사원 결혼 축하금을 승인했습니다" |
| 확인 | 질문형 제목 + 되돌릴 수 없는 결과 설명 | "이 카드를 삭제할까요?" / "지난 결제 내역은 남고…" |
| 버튼 | 동사로 끝냄, "확인" 남용 금지 | "이체하기" "다시 보내기" "동의하고 다음" |

**말투: 콘솔 전체 합니다체로 통일 (적용 완료).** 콘솔 문구 대부분이 이미 합니다체라, 로그인 화면에 남은 해요체 19건을 바꿨다 (예: "번호예요" → "번호입니다", "준비됐어요" → "준비되었습니다"). 요청은 "~하세요"를 쓴다.

## 5. 체크리스트 (새 화면 만들 때)

- [ ] 필수 입력이 비면 CTA가 비활성인가, 이유가 화면 안에 보이는가
- [ ] 형식 오류는 필드 자리에서 알리는가 (팝업 금지)
- [ ] 돈 · 발송 · 삭제 전에 Alert로 한 번 확인하는가
- [ ] 저장 결과는 Toast, 발송 결과는 완료 모달로 구분했는가
- [ ] 실패 상태는 목록 배지로 남고, 그 자리에서 고칠 수 있는가
- [ ] 비어 있을 때 FallbackView가 있는가
