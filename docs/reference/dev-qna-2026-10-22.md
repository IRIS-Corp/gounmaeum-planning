**먼저 전제 하나를 바꿨습니다.** plan.md가 "시안 · 명세서 · decisions.md보다 우선"이었던 게 이번 혼선의 원인입니다. A-1 · A-3이 둘 다 **plan.md가 `decisions.md`를 너무 줄여 적어서** 생긴 것이었습니다. 그래서 plan.md 머리글을 이렇게 바꿨습니다.

> plan.md는 **시안에서 보이는 화면보다** 우선합니다. 다만 plan.md는 `decisions.md`의 **요약**이고, 요약과 원래 결정이 다르면 **`decisions.md`가 맞습니다.**

## A. plan.md와 시안이 다른 것

### A-1. 예금주 확인 — **시안이 맞습니다. 개발한 대로 두세요.**
`decisions.md` **D27**(2026-10-14 확정)에 이미 나뉘어 있습니다.

| 받는 사람 | 규칙 |
|---|---|
| 임직원 | **막는다.** 본인 명의 계좌만 허용("본인 명의 계좌가 아닙니다"). 비교 기준은 임직원 본인 이름, 띄어쓰기 · 앞뒤 공백 무시 |
| 거래처 · 외부 | **막지 않는다.** 이름 비교 없음. 조회 결과만 보여 주고 "확인하고 송금" |

plan.md가 거래처 규칙만 적고 임직원 규칙을 빠뜨렸습니다. plan.md를 D27대로 고쳤습니다.

- 질문 1: **임직원은 이름 비교를 유지합니다.** 가족 · 법인 명의로는 못 보냅니다.
- 질문 2: **"임직원 본인 명의 계좌로만 지급" 원칙은 그대로입니다.**

### A-2. 부고장 링크 만료 — **열람 기간 제한을 없앱니다. 개발의 +2년 차단도 푸세요.**
사용자 확인(2026-10-22). 아이리스 · 부고드림 두 서비스 코드를 확인한 결과입니다.

- 아이리스: 발인 시각이 지나면 "발인이 완료된 상가입니다" 안내 창. 발인일 +5일까지는 [확인]으로 닫고 볼 수 있고 그 뒤에는 확인 버튼이 없어 사실상 못 봄. (서버에서 7일 뒤 막는 코드는 2022년부터 꺼져 있음)
- 부고드림: 같은 안내 창은 뜨지만 **기간 제한 없이 계속 열람 가능**
- **고운마음은 부고드림에 맞춥니다.** 발인 후 안내 창을 띄우고, 확인하면 그 뒤에도 봅니다. 발인 뒤 수정은 불가.
- **"30일 만료"는 없어졌습니다.** 두 서비스 코드에 그런 기준은 없었습니다.
- **"기록 2년 보관"도 같이 없어집니다.** 링크를 기한 없이 열려면 그 부고장 데이터가 계속 있어야 하므로 둘을 따로 둘 수 없습니다. 2년은 원래 "링크 30일"과 한 묶음이던 값(C1)이었습니다.
- 그래서 **개인정보 보관 기간은 법무 확인 대상으로 올렸습니다**(plan.md 5장 미정 8). 고인 · 상주 · 부의금 계좌가 기한 없이 남기 때문입니다. 나중에 보관 기간을 다시 두면 그게 곧 공개 링크 수명이 됩니다.

### A-3. 증빙 필수 범위 — **시안이 맞습니다. 발송별로 다릅니다.**
`decisions.md` **D32**(2026-10-19 확정) 그대로입니다.

| 발송 | 증빙 | 필수 |
|---|---|---|
| 경조금 · 거래처 | 부고장 · 청첩장 | 항상 |
| 화환 | 부고장 · 청첩장 | **거래처 · 직접 입력일 때만** (등록된 경조사는 생략) |
| 부고장 · 직접 입력 | 사망진단서 · 장례식장 안내 · 부고 문자 캡처 | 항상 |
| 부고장 · 등록된 경조사 | — | 없음 (등록 · 승인 때 이미 확인) |
| 임직원 경조사 | 복지 정책 + 본인 계좌 송금 기록 (D27 §3) | 부고장 첨부는 필수 아님 · 사후 제출 허용 |

- 질문 1: **필수는 "거래처 발송(경조금 항상 · 화환 거래처/직접입력)"과 "부고장 직접 입력"입니다.** 임직원 경조사 등록은 필수가 아닙니다.
- 질문 2: **제출 기한은 이미 정해져 있습니다 — D4: 14일 · 자동 요청 · 회사 설정.** DB의 제출 기한 칸과 홈 "서류 대기"를 그대로 쓰면 됩니다. 기한이 지나면 자동 요청 문자가 한 번 더 나가고, 건은 신청 · 승인 화면에 남습니다(막지는 않습니다).
- **거래처 화환에 첨부 칸이 없는 것은 시안 누락입니다.** D32대로 첨부 칸이 있어야 합니다. 명세서 "거래처 발송" 절의 화환 3단계에는 "서류 첨부 (필수)"로 적혀 있습니다. 시안을 고치겠습니다.

### A-4. 송금 수수료 — **(나) 회사가 더 부담합니다.**
사용자 확인(2026-10-22).

- 받는 분은 **정책 금액 전액**을 받습니다. (가) 차감 방식이 아닙니다.
- 수수료는 **회사 결제금액에 더해** 보여 줍니다. 시안 요약(`부의금 ₩500,000 · 송금 수수료 ₩500 · 합계 ₩640,500`)이 맞습니다.
- 수수료 **금액**은 PG 확정 후입니다(plan.md 5장 미정 2).

### A-5. 장례케어 — **화면은 "준비 중"으로 두고, 필수 표시(`*`)는 뺍니다.**
MVP 제외(D28)인데 필수 입력일 수는 없습니다. 개발이 잠가 둔 것이 맞습니다. 시안에서 `*`와 "장례지도사 출동 · 상조 서비스가 함께 진행됩니다" 문구를 정리하겠습니다. 경조사 상세의 장례케어 상태 줄은 참고용으로 남깁니다.

### A-6. 법인카드 한도 초과 — **미정으로 돌립니다. 지금은 "사용 중지"로 개발해 주세요.**
`decisions.md` 안에서 충돌이 있습니다.

- **C5**: 월 한도 도달 시 그 카드 사용 중지 · 문의
- **D27 권한 절**: "대표만 — 법인카드 한도 초과 결제 승인"
- 명세서 9장 **Q2**: "해당 없음 — 한도 초과 승인 흐름 삭제"

plan.md 권한표에서 "한도 초과 승인" 행을 빼고 5장 미정 4로 옮겼습니다. 당장은 **C5(사용 중지 + 문의)**로 만들어 주세요. 시안의 "초과 시 승인" 문구도 함께 정리하겠습니다. PG 계약 뒤에 다시 정합니다.

## B. 일반(임직원) 계정 승인 흐름

### B-1. 승인 전 발송 범위 — **개발 임시안이 맞습니다. 부고장 예외는 두지 않습니다.**
사용자 확인(2026-10-22). 확인되지 않은 부고가 사내에 나가는 것을 막는 쪽을 택했습니다.

- 질문 1: **예외 없음.** 화환 · 경조금 · 부고장 모두 승인 후 진행합니다.
- 질문 2: 알림 수단은 **미정**입니다(plan.md 5장 미정 6). 콘솔 알림이 개발 전이라, 1차는 **문자**가 현실적입니다. 발인 D-2 이내 건은 알림을 세게 하는 것으로 방향만 잡았고, 문구 · 발송 조건은 따로 드리겠습니다.

### B-2. 일반이 등록할 수 있는 대상 — **본인 · 본인 가족 건만입니다.**
사용자 확인(2026-10-22).

- 질문 1: **본인(과 본인 가족) 경조사만.** 다른 임직원 건은 등록하지 않습니다.
- 질문 2: plan.md의 "본인 건"은 **"본인이 등록한 건"**입니다. 등록 대상이 본인으로 묶이니 둘이 같아집니다.
- **시안 더미 데이터가 틀렸습니다.** 코드의 `vwRows`에 박철수 차장 부친상 · 정재훈 사원 결혼 · 김도현 부장 모친상 3건이 들어 있고 로그인 계정은 한서연 팀장입니다. 전부 남의 건입니다. 본인 건으로 바꾸겠습니다.

### B-3. 자동 승인 기준 — **당장은 개발 임시안대로 전부 승인 필요.**
기준 금액은 미정입니다(plan.md 5장 미정 1). 정해지면 **회사별 설정**(복지 정책 화면)으로 갈 가능성이 높습니다 — 정책 금액이 이미 회사별 설정(Q1)이라 같은 화면에 붙는 게 자연스럽습니다. 확정 전까지 공통 하드코딩은 피해 주세요.

### B-4. 시안 문구 — **전부 시안 쪽 잘못입니다. 고치겠습니다.**
| 위치 | 현재 | 고칠 것 |
|---|---|---|
| 일반 등록 화면 안내 | "등록하면 경조사가 만들어지고 선택한 발송이 진행됩니다" | 승인 요청 흐름에 맞게 교체 |
| 일반 홈 안내 카드 | "보기 전용 계정입니다 / …할 수 있습니다" | "일반 계정입니다 / …관리자 승인 후 진행됩니다". "보기 전용"은 2026-10-15에 **일반**으로 통일하며 없어진 이름입니다 |
| 일반 설정 입구 | 빌드가 숨김(`showSettingsNav: !isViewer`) | **문서가 맞습니다.** 입구를 보이게 하고, 안에서 조직 · 관계 / 복지 정책 / 회사 정보 3개 탭만 **읽기**로. 개발 예정대로 가 주세요 |

### B-5. 일반의 거래처 발송 — **거래처 목록을 검색 · 선택할 수 있어야 합니다.**
보내려면 받는 곳을 고를 수 있어야 하므로, 보내기 화면에서는 거래처 검색 · 선택을 허용합니다. 직접 입력도 그대로 됩니다. 사이드바 "거래처" **관리** 메뉴만 없는 것입니다(추가 · 수정 · 삭제 불가). plan.md 2장 B에 적었습니다.
