# 정책 질문 10건 검토 (2026-10-12)

각 항목: **결론 → 이유 → 화면 · 동작 → 예외 · 주의 → 남는 질문**

---

## 1. 알림을 누르면 어디로 가나 (회사 정보 수정 요청 반려)

**결론** 별도 알림 상세 페이지 없이, 알림 → 설정 › 회사 정보로 이동. 그 화면 맨 위에 "최근 요청 결과"를 보여 준다.

**이유**
- 반려 사유는 "그래서 무엇을 다시 해야 하는지"와 함께 봐야 의미가 있다. 다시 요청하는 곳이 회사 정보 화면이므로 그 자리에서 사유를 보여 주는 게 가장 짧은 동선이다.
- 알림 상세 페이지를 따로 만들면 사유를 보고 → 다시 회사 정보로 이동하는 단계가 한 번 더 생긴다.

**화면 · 동작**
- 회사 정보 화면 맨 위 안내 박스 (주의색)
  - 제목: "회사명 변경 요청이 반려되었습니다 · 10/11"
  - 본문: 반려 사유 원문 (예: "첨부한 사업자등록증의 상호와 입력한 회사명이 다릅니다")
  - 버튼: "다시 요청" → 같은 항목이 선택된 수정 요청 창 열림 · "닫기"
- 승인된 경우도 같은 자리에 "승인되었습니다 · 반영 완료" (정보색)로 1회 표시
- 닫으면 다시 보이지 않음. 지난 결과는 "요청 이력"(작은 텍스트 버튼)에서 목록으로 확인
- 알림 패널의 해당 알림을 누르면 이 화면으로 이동하고 안내 박스가 열린 상태

**예외 · 주의**
- 같은 항목에 반려가 여러 번이면 가장 최근 1건만 박스로, 나머지는 요청 이력에
- 관리자 계정도 결과는 볼 수 있음 (요청 버튼만 없음)

**남는 질문** 반려 사유는 고운마음 담당자가 자유 입력인지, 정해진 사유 목록인지 (목록이면 사유별 "다시 하는 방법" 안내 문구를 붙일 수 있음)

## 2. 회사 정보 수정 요청(회사명 · 사업자등록번호 · 대표자명)을 누가 보낼 수 있나

**결론** 대표(Owner) 계정만.

**이유**
- 세 항목은 계약 당사자 정보 · 세금계산서 발행 정보다. 잘못 바뀌면 정산과 증빙이 모두 틀어진다.
- 사업자등록증 원본을 갖고 있고 책임지는 사람은 대표 쪽이다.

**화면 · 동작**
- Owner: "사업자 정보" 섹션에 "수정 요청" 버튼
- 관리자: 버튼 숨김 + 섹션 아래 한 줄 "사업자 정보 변경은 대표 계정에서 요청합니다"

**예외 · 주의**
- 관리자가 대신 처리해야 하는 상황(대표 부재)은 Owner 권한 이관으로 해결. 콘솔에 우회 경로는 두지 않는다.

## 3. 회사 주소 · 대표 연락처를 누가 고칠 수 있나 (권장안 없음 → 제안)

**결론** 대표 + 관리자 모두 수정 가능. 고친 내용은 활동 로그에 남긴다.

**이유**
- 주소 · 연락처는 계약 정보가 아니라 운영 정보다. 화환 기본 배송지 · 문자 회신 번호로 쓰인다.
- 사무실 이전 · 대표번호 변경은 보통 총무 · 인사 담당(관리자)이 처리한다. 대표만 고칠 수 있으면 대표에게 매번 부탁해야 한다.
- 승인 절차 없이 바로 반영해도 되는 이유: 잘못 고쳐도 다시 고치면 되고, 법적 효력이 없다.

**화면 · 동작**
- "주소 · 연락처" 섹션의 "수정" 버튼을 관리자에게도 보여 줌
- 저장하면 토스트 "주소를 바꿨습니다" + 활동 로그 "변경 이력 · 회사 주소 · 한서연 팀장 · 이전 값 → 새 값"

**남는 질문** 본부 담당(조회 위주) 권한까지 열지 → 열지 않는 것을 추천

## 4. 회사 정보 수정 요청을 한 번에 여러 건 보낼 수 있나

**결론** 항목별 동시 허용. 같은 항목은 검토 중이면 새 요청을 막는다. 등록증은 가장 나중에 승인된 요청의 파일이 최신.

**이유**
- 상호와 대표자가 함께 바뀌는 경우(합병 · 대표 교체)가 있다. 한 건씩만 받으면 앞 요청이 끝날 때까지 며칠 기다려야 한다.
- 같은 항목을 두 번 보내면 어느 쪽이 맞는지 고운마음이 판단할 수 없으니 막는다.

**화면 · 동작**
- 사업자 정보 각 줄 오른쪽에 상태 배지: "검토 중" (주의색)
- 수정 요청 창에서 검토 중인 항목은 체크할 수 없고, 옆에 "검토 중 · 10/11 요청" 표시
- 검토 중인 요청은 "요청 취소" 가능 (요청 이력에서)

**예외 · 주의**
- 회사명(A 등록증)과 대표자명(B 등록증)을 따로 보내고 둘 다 승인되면 최종 등록증은 B. 그런데 B가 회사명 변경 전 등록증이면 상호가 다를 수 있다.
  → 두 번째 요청을 보낼 때 "검토 중인 회사명 변경이 있습니다 · 바뀐 상호가 적힌 등록증을 첨부하세요" 안내를 띄운다.
- 더 안전한 대안: 한 요청에 여러 항목을 함께 체크해 등록증 1장으로 보내게 유도 (이미 시안의 요청 창은 여러 항목 체크 가능)

## 5. 조직(본부 · 팀) 순서 바꾸기

**결론** 필요. 위 · 아래 버튼. 대표 + 관리자. CSV로 만든 조직은 파일에 나온 순서.

**이유**
- 가나다순은 회사 조직도와 맞지 않는다 (경영 > 영업 > 개발 순서가 깨짐).
- "10팀"이 "2팀"보다 먼저 나오는 문제는 정렬 방식만 바꿔도 해결되지만, 조직도 순서 문제는 직접 정해야 한다.
- 끌어서 옮기기는 휴대폰 · 터치패드에서 어렵고, 개발 비용도 크다. 위 · 아래 버튼이면 충분하다.

**화면 · 동작**
- 설정 › 조직 · 운영 › 본부 · 팀 목록 각 줄 오른쪽에 ↑ ↓ 아이콘 버튼 (맨 위는 ↑ 비활성, 맨 아래는 ↓ 비활성)
- 팀은 본부 안에서만 움직인다 (다른 본부로 옮기기는 "본부 이동"으로 별도)
- 바꾼 순서는 바로 저장 · 토스트 "순서를 바꿨습니다"
- 이 순서가 쓰이는 곳: 본부 필터 · 임직원 목록 · 리포트 본부별 집계 · 담당자 선택 목록

**예외 · 주의**
- CSV를 다시 올려서 새 본부가 생기면 기존 순서 맨 아래에 추가 (기존 순서는 유지)
- 숫자가 섞인 이름("2팀 · 10팀")은 처음 생성 시 숫자 크기순으로 정렬 (자연 정렬)

## 6. 퇴사 처리에 미래 날짜(퇴사 예정) 허용

**결론** 허용. 그날까지 "퇴사 예정"으로 재직, 그날 자동 퇴사. 그 전에는 취소 가능.

**이유**
- 퇴사일이 정해지는 시점과 실제 퇴사일 사이에 간격이 있다. 담당자가 그날 직접 처리해야 하면 놓친다.

**화면 · 동작**
- 퇴사 처리 창: 퇴사일 날짜 선택 (기본값 오늘). 미래 날짜를 고르면 안내 "10/31에 자동으로 퇴사 처리됩니다 · 그 전까지 신청 · 로그인 가능"
- 목록 · 상세 상태 배지: "퇴사 예정 10/31" (주의색)
- 상세 더보기 메뉴: "퇴사 처리" 대신 "퇴사 예정 취소"
- 당일 자동 처리: 로그인 차단 · 관리자 권한 해제 · 활동 로그 "자동 퇴사 처리"

**예외 · 주의**
- 퇴사 예정인 사람이 관리자면, 예정일 3일 전에 "대행자를 지정하세요" 알림 (권한이 갑자기 비지 않도록)
- 퇴사 예정 중 경조사 신청은 허용 (재직 중이므로)

## 7. 경조 이력이 있는 임직원을 삭제할 수 있나

**결론** 이력이 있으면 삭제 불가. 퇴사 처리로 안내.

**이유**
- 삭제는 "잘못 등록한 사람 정리"용이다. 이력이 있는 사람을 지우면 정산 · 리포트 · 증빙의 대상자가 사라진다.

**화면 · 동작**
- 이력이 있는 사람의 더보기 메뉴에서 "임직원 삭제"는 비활성 + 마우스를 올리면 "경조 이력이 있어 삭제할 수 없습니다 · 퇴사 처리를 이용하세요"
- 이력이 없는 사람만 삭제 창 (사유 필수 · 기록은 남김)

## 8. 여러 기업에 가입된 휴대폰 번호 변경

**결론** 한 기업 소속이면 그 콘솔에서 변경. 여러 기업 소속이면 콘솔에서 막고 고운마음 고객센터로 안내.

**이유**
- 휴대폰 번호는 기업을 가리지 않는 하나의 로그인 ID다. 계열사 담당자가 바꾸면 지주사 콘솔 로그인도 바뀐다. 한 기업이 다른 기업 계정에 영향을 주면 안 된다.

**화면 · 동작**
- 번호 변경 버튼은 똑같이 보이되, 누르면 여러 기업 소속인 경우 변경 창 대신 안내 창
  - "이 번호는 2개 회사(선진건설 · 선진홀딩스)에 등록되어 있습니다 · 번호를 바꾸면 모든 회사의 로그인이 함께 바뀌므로 고운마음 고객센터에서 변경합니다"
  - 버튼: "고객센터 문의" · "닫기"
- 기본 정보에 "다른 회사에도 등록됨 · 2곳" 작은 표시 (관리자가 미리 알 수 있게)

**예외 · 주의**
- 다른 회사 이름을 보여 주는 게 개인정보 · 영업정보 문제인지 확인 필요 → 문제가 되면 "다른 회사에도 등록된 번호입니다"로만 표시

## 9. 퇴사자 정보 수정

**결론** 막음 (보기만). 고칠 일이 있으면 퇴사 취소 후 수정.

**이유**
- 퇴사자 정보는 퇴사 시점의 기록이다. 정산 · 증빙 기준이 되므로 나중에 바뀌면 안 된다.

**화면 · 동작**
- 퇴사자 상세: 기본 정보 "편집" 버튼 비활성 + 안내 "퇴사한 임직원은 정보를 바꿀 수 없습니다 · 고치려면 퇴사를 취소하세요"
- 더보기 메뉴: "퇴사 취소"

**예외 · 주의**
- 퇴사 취소는 Owner만 할 수 있게 하는 것을 추천 (기록 변경이므로). 퇴사 취소 → 수정 → 다시 퇴사 처리가 모두 활동 로그에 남는다.
- 오타 수준 수정이 잦다면 2차에 "기록 정정"(사유 필수 · Owner만) 기능을 별도로 둘 수 있음

## 10. 다른 본부 소속 사람을 본부 담당자로 지정

**결론** 허용으로 통일. 조직 화면에서도 다른 본부 사람을 고를 수 있게.

**이유**
- 한 사람이 여러 본부를 맡는 경우가 흔하다 (경영지원 김부장이 영업 · 개발 접수도 담당).
- 지금은 권한 화면에서는 되고 조직 화면에서는 안 되어, 같은 일을 하는데 결과가 다르다.

**화면 · 동작**
- 조직 화면 담당자 선택 창: 기본은 그 본부 소속이 위에, 아래 "다른 본부" 묶음으로 전체 임직원 검색
- 다른 본부 사람을 고르면 이름 옆에 "경영지원본부 소속" 작은 표시
- 권한 화면과 조직 화면은 같은 데이터를 본다 (한쪽에서 지정하면 다른 쪽에도 반영)
