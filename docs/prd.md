## 1. 제품 개요
- 기업 인사총무 담당자가 임직원·거래처의 경조사(부고·결혼·출산·회갑 등)를 접수하고, 화환·경조금·부고장을 발송하고, 신청을 승인하고, 예산을 정산하는 B2B 데스크톱 콘솔. [README Overview]
- 대상 뷰포트 데스크톱 1280~1920px, 모바일 대응 없음. [README Global Layout]

## 2. 사용자
- 핵심 사용자: 회사당 인사총무 담당자 1~2명(파워유저). [README Overview]
- 경조사가 발생했을 때만 급하게 쓰는 도구. 평소에는 비어 있는 시간이 훨씬 김(월 1~2건). [README Overview]
- 권한 4단계: Owner / 관리자 / 본부 담당 / 조회. [README 권한 정의]
- 거래처는 콘솔 사용자가 아니라 **발송 대상**(선진건설의 협력사). 거래처 쪽 로그인 사용자는 없음. [대화]
- 임직원이 직접 경조 신청을 올림. 신청 채널은 **웹**(확정). 임직원 신청 웹은 콘솔과 별도 화면이며 같은 계정(휴대폰 번호)으로 로그인. [README 2. 신청·승인 · 대화]

## 3. 주요 작업 흐름 (JTBD)
1. 부고 접수 → 화환·경조금 즉시 발송 [README Overview]
2. 경조 신청 접수 → 증빙 검토 → 승인 [README Overview]
3. 예산·정산 리포트 확인 [README Overview]
- 경조사 접수 = 한 건의 경조사를 등록하고 여러 발송을 묶는 행위, 단건 발송 = 경조사와 무관하게 한 건씩 보내는 행위. [대화]

## 4. 제품 원칙
- 속도와 명확성이 최우선. [README Overview]
- 빈 상태를 먼저 설계. 각 섹션마다 "무엇이 없는지 + 지금 무엇을 할 수 있는지". [README 구현 시 주의사항 1]
- Primary 버튼은 화면당 하나. [README 구현 시 주의사항 4]
- 단일 소스: 임직원 명부·권한·템플릿 개수·부고 정보는 한 곳에서만 정의. [README 구현 시 주의사항 2]

## 5. 규칙 (어기면 사고가 나는 것 후보)
- 신청 승인은 **건마다 증빙을 보고 단건 처리**. 체크박스·일괄 승인 없음. [README 2. 신청·승인]
- 반려 사유는 필수이며 신청자에게 문자로 그대로 전달. [README 2. 신청·승인]
- 경조금 입금 계좌는 매번 입력 + 예금주 조회로 검증. [README 경조금 보내기]
- 발송 채널은 문자(LMS). 알림톡 아님. [README 구현 시 주의사항 6]
- 법인카드 한도 초과 결제는 승인 후 결제. 기본 승인자는 Owner, 회사마다 다를 수 있음. [README 권한 정의 · 대화]

- 이체 실패 건은 계좌 · 예금주를 다시 조회한 뒤 다시 보냄. [대화 · 확정]
- 부고장 공개 링크는 발인 후 30일 만료, 기록 2년 보관. [대화 · 확정]
- 정책 금액 · 한도 초과 승인자는 회사별 설정. 기본 승인자 Owner. [대화 · 확정]
- **기획 문서에 없는 기능은 만들지 않음.** 시안에 있어도 문서에 없으면 1차 범위에서 제외. [대화 · 확정]

## 6. 화면 범위
홈 · 신청·승인 · 경조사(목록·상세) · 경조사 접수 · 단건 발송(화환·경조금·부고장) · 리포트·내역 · 마일리지 · 임직원 · 거래처 · 설정(복지 정책·법인카드·문자·조직·회사 정보·부고장 서식·권한). [README Screens]
