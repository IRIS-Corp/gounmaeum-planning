표기: **입력** 사용자가 넣는 것 · **규칙** 시스템이 판단하는 것 · **결과** 성공 시 · **예외** 실패 · 막힘.

### S-LOGIN 로그인 — P1
상세 흐름은 `docs/login-flow.md`가 기준입니다.

| ID | 기능 | 입력 | 규칙 | 결과 | 예외 |
|---|---|---|---|---|---|
| F-LOGIN-1 | 로그인 | 휴대폰 번호 + 비밀번호 | ID = 휴대폰 번호. 등록된 번호만 허용 | 홈 진입 | 번호 미등록 · 비밀번호 불일치 → 입력칸 아래 오류. 5회 실패 시 10분 잠금 |
| F-LOGIN-2 | 최초 로그인 | 휴대폰 번호 → 인증번호 6자리 → 새 비밀번호 2회 | 인증번호 3분 유효 · 재발송 60초 후 · 비밀번호 8자 이상, 영문+숫자 | 비밀번호 저장 후 홈 진입 | 인증 만료 · 불일치 → 입력칸 오류 + 재발송 버튼 |
| F-LOGIN-3 | 비밀번호 재설정 | 휴대폰 번호 → 인증번호 → 새 비밀번호 | F-LOGIN-2와 같음 | 로그인 화면 복귀 + 토스트 | 같음 |
| F-LOGIN-4 | 로그인 상태 유지 | 체크박스 | 켜면 30일 유지 (가안) | — | — |
| F-LOGIN-5 | 번호 변경 안내 | "번호가 바뀌었나요?" | 본인 변경 불가 · 관리자에게 요청 | 안내 창 (M-phoneChange) | — |
| F-LOGIN-6 | 약관 · 개인정보 보기 | 링크 | — | 내용 창 (M-terms · M-privacy) | — |

### S-HOME 홈 — P1

| ID | 기능 | 규칙 | 결과 |
|---|---|---|---|
| F-HOME-1 | 처리할 일 목록 | 내 담당 범위의 건 중 다음 행동이 필요한 것만. 정렬: 발인 임박 → 승인 대기 → 서류 대기 | 줄마다 상태 배지 · 제목 · 설명 · 행동 버튼 1개 |
| F-HOME-2 | 요약 칸 (발인 임박 · 승인 대기 · 서류 대기) | 숫자 = 위 목록의 해당 건수. 누르면 목록 필터, 다시 누르면 해제 | 목록 걸러짐 |
| F-HOME-3 | 줄 안 행동 | 부고장 발송 → S-SEND-F(부고장) · 축하금 승인 → 확인 창(M-quickApprove) · 서류 요청 → M-proofRequest | 처리 후 목록에서 빠지고 토스트 · 사이드바 숫자 감소 |
| F-HOME-4 | 단건 발송 바로가기 | 화환 · 경조금 · 부고장 카드 3개 | 해당 보내기 화면을 빈 상태로 열기 |
| F-HOME-5 | 시작 가이드 (빈 상태) | 회사 설정 단계 중 안 끝난 것이 있을 때만 표시. 단계별 완료 체크 | 모두 끝나면 숨김 |

### S-SEND-F 보내기 (단계식) — P1

| 종류 | 단계 | 필수 | 완료 |
|---|---|---|---|
| 화환 | 1 받는 사람 → 2 상품 · 배송 → 3 결제 | 받는 사람 · 배송지 · 상품 | 결제 후 주문 · 완료 창 "경조사 보기 / 하나 더 보내기" |
| 경조금 | 1 받는 사람 + 입금 계좌 → 2 금액 → 3 출금 계좌 · 문자 안내 | 받는 사람 · 예금주 조회 통과 · 금액 | 이체 + 안내 문자 |
| 부고장 | 1 경조사 · 수신 대상 → 2 발송 확인 | 경조사 · 수신 대상 1개 이상 | 문자 발송 (비용 없음) |

| ID | 기능 | 규칙 |
|---|---|---|
| F-SEND-1 | 받는 사람 검색 | 임직원 · 거래처 · 직접 입력. 진행 중 경조사가 있는 임직원은 배지 표시 |
| F-SEND-2 | 화환 상품 | 상황 칩(근조 · 축하 · 개업 · 승진) · 페이지네이션 · 반입 제한 상품 비활성 |
| F-SEND-3 | 리본 문구 | 왼쪽(문구) · 오른쪽(보내는 사람 이름 = 설정의 발신 명의) |
| F-SEND-4 | 마일리지 사용 (P2) | 1P = 1원 · 상품 금액까지 · 결제액 4% 적립 (가안) |
| F-SEND-5 | 경조금 금액 | 관계별 정책 금액 자동 · +10만/+30만/+50만 · 정책과 다르면 승인 필요 |
| F-SEND-6 | 부고장 수신 대상 | 사내 전체 · 거래처 · 부서 단위 · 개별 추가. 각 명단 "상세 보기"에서 체크 / 해제. 임원 우선 발송은 1차 제외 |
| F-SEND-7 | 단계 이동 | 현재 단계 필수 미충족 시 "다음" 비활성 + 남은 항목 안내 |

## 3. 상태 전이

### 3-1. 경조사
```
접수 ──(정책 자동 승인 or 관리자 승인)──▶ 결재
결재 ──(화환·경조금·부고장 중 하나라도 실행)──▶ 진행
진행 ──(모든 보낼 것이 완료/실패 확정 + 발인 다음 날 + 서류 확인)──▶ 완료
어느 단계든 ──(경조사 취소)──▶ 취소   ※ 실행된 발송은 되돌리지 않음
```
| 상태 | 보이는 이름 | 다음 행동 | 홈 처리할 일 |
|---|---|---|---|
| received | 접수 | 승인 | 승인 대기 |
| approved | 결재 | 발송 | 발인 임박 (D-2 이내) |
| sending | 진행 | 실패 건 재작성 · 서류 확인 | 이체 실패 · 서류 대기 |
| done | 완료 | — | — |
| canceled | 취소 | — | — |

⚠️ 이전 명세의 5단계(접수 · 승인 · 발송 · 정산 · 완료)를 v0.3.0 결정에 맞춰 4단계로 줄였습니다. 없어진 **정산** 단계가 하던 "서류 확인"을 위에서는 **진행**에 넣었습니다. 서류 확인을 별도 단계로 다시 둘지는 확인이 필요합니다 (9장 Q10).

### 3-2. 신청 (임직원 웹 → 콘솔)
`대기 → 승인(→ 경조사 결재 단계와 연결)` · `대기 → 반려(종료)` · `대기 → 서류 요청 → 대기`

### 3-3. 발송
| 종류 | 상태 흐름 | 실패 처리 |
|---|---|---|
| 화환 | 접수 → 배송 준비 → 배송 중 → 배송 완료 / 취소 요청 → 취소 | 반입 제한 → 대체 상품 승인 |
| 경조금 (부의금) | 처리 중 → 이체 완료 / 이체 실패 | **재시도 없음**. 계좌 수정 후 새 건 |
| 경조금 (축의금) | 예약 → 처리 중 → 이체 완료 / 이체 실패 | 같음 |
| 부고장 | 발송 대기 → 발송 완료 / 일부 실패 | 실패 번호만 재발송 |

송금 시점: **부의금은 승인 즉시**, **축의금은 행사 당일 10:00 예약 송금**. 화환은 근조는 즉시 주문, **축하 화환은 행사 N일 전 주문만** 받습니다 (N = 회사별 설정 · 가안).

### 3-4. 결제 (법인카드 월 한도)
`결제 요청 → (월 한도 이내) 승인 완료` · `결제 요청 → (월 한도 도달) 결제 막힘 → 카드 사용 중지 + 문의 안내`

한도를 넘겨 Owner가 승인하던 흐름은 삭제됐습니다. 한도에 닿으면 결제가 되지 않고, 한도를 올리는 것은 설정 › 법인카드에서 Owner가 합니다.

## 4. 권한

역할은 **Owner**(회사당 1명 · 계약 시 백오피스가 지정) · **관리자** · **뷰어** 3단입니다. 임직원은 신청 웹만 쓰고 콘솔에 들어오지 않습니다.

Owner와 관리자는 **같은 권한**입니다(10-12 · 법인카드 등록 · 한도도 관리자 가능). 뷰어는 **보이는 메뉴가 홈과 단건 발송으로 줄고**, 설정은 3개 탭만 읽기 전용으로 보입니다. 실행은 단건 발송과 경조사 등록까지만 됩니다.

아래 뷰어 열은 프로토타입 v0.3.6의 `navShown` · `settingsTabItems` 필터를 그대로 적은 것입니다.

**부재 처리**

주 담당자가 휴가이거나 24시간 안에 처리하지 않은 건은 **대행자**에게 넘어갑니다. 대행자는 설정 › 권한에서 지정합니다.

v0.3.0에서 **본부 담당 · 조회** 역할은 없어졌습니다. 본부 단위로 보이는 범위를 제한하지 않습니다. 다만 프로토타입 v0.3.6의 설정 › 법인카드 권한 안내 모달 문구에 "본부 담당"이 아직 남아 있습니다 — 문서가 아니라 **프로토타입 쪽 수정 대상**입니다 (9장 Q11).

권한 없는 메뉴는 **숨김**(사이드바에서 제외), 권한 없는 버튼은 **비활성 + 툴팁 "권한이 없습니다"**.

형식 공통: 금액 정수(원) · 날짜 ISO 8601 · 휴대폰 `010-0000-0000` 저장은 숫자만.

## 8. 공통 규칙

- **오류 안내**: 입력 오류는 입력칸 빨간 테두리 + 아래 문구. 저장 성공은 토스트. 되돌릴 수 없는 행동(취소 · 삭제 · 반려 · 이체)은 확인 창. → `docs/validation-ui.md`
- **버튼 활성**: 필수 미충족 시 비활성 + 근처에 남은 항목 안내. 한 화면 파란(주) 버튼 1개.
- **빈 상태**: 모든 목록 · 표는 빈 상태 문구 + 다음 행동 버튼. 시안의 "빈 상태" 전환으로 확인.
- **숫자 표기**: 금액 `₩1,000,000` · 건수 `N건` · 날짜 `5/21 (수) 06:00`.
- **정책 버전 고정**: 경조사는 등록 시점 정책 버전을 저장하고 이후 변경에 영향받지 않음.
- **감사 기록**: 승인 · 반려 · 이체 · 정책 변경 · 권한 변경 · 내보내기는 활동 로그에 남김.

### 8.x 목록 페이지 규칙

| 항목 | 규칙 |
|---|---|
| 한 페이지 행 수 | **10행** (표 · 목록 공통) |
| 페이지네이션 표시 | 전체가 10행 **초과**일 때만 표시 · 10행 이하면 숨김 |
| 위치 | 표 아래 **가운데 정렬** |
| 번호 묶음 | 5페이지씩 · 처음 · 이전 · 다음 · 끝 버튼 |
| 1페이지로 돌아가는 경우 | 탭 · 필터 · 검색어 · 정렬을 바꿨을 때 |
| 유지되는 경우 | 상세를 열었다 목록으로 돌아올 때 (이전 페이지 유지) |
| 예외 | 홈 처리할 일 · 알림 · 모달 안 목록은 페이지 없이 전체 표시 (모달은 본문 스크롤) |

예시: 임직원 152명 → 16페이지 · 결제 내역 24건 → 3페이지 · 신청 · 승인 4건 → 페이지네이션 없음

### 8.y 빈 상태 버튼 규칙

| 경우 | 빈 상태 안 버튼 |
|---|---|
| 같은 화면 위쪽(툴바 · 헤더 · 사이드바)에 같은 동작 버튼이 있음 | **넣지 않음** — 제목 · 설명만 |
| 필터 · 검색 결과가 0건 | "필터 초기화"만 (위쪽에 없는 동작) |
| 화면 어디에도 시작 동작이 없음 | 넣음 (예: 시작 단계 안내) |

적용: 화환 · 경조금 · 부고장 목록, 임직원, 홈 처리할 일, 경조사 목록(데이터 없음) → 버튼 제거
